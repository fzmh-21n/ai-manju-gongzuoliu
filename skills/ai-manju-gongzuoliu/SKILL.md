# AI漫剧工作流

把用户的完整文章转成可追踪资产、角色图、场景图和分节视频提示词。严格按七步顺序执行，不跳过强制询问。

## 最高优先级

1. **只使用一套统一视频提示词。** 两份旧导演提示词 `references/director-vertical-realistic.md` 与 `references/director-horizontal-3d.md` 已废止，禁止读取、参考或调用。所有视频分镜只读取并执行用户提供的 `references/director-unified-xiaoliuyue-15s.txt`。两种作品的角色图和场景图统一使用16:9，只切换风格描述词；最终视频提示词才按类型切换为仿真人竖屏9:16或漫剧横屏16:9。
2. **准确映射已生成资产。** 每节的【出场人物】按“本节现场实际存在的人”确定，不按是否说话确定；【出场人物】、主提示词中的“人物资产只使用……”和画面实际人物必须完全一致。人物和场景只允许使用资产库中的精确原始文件名，不得临时编造、近似替代或在视频提示词中写“新增，需新出图”；缺少资产时先报告并停止该节，待资产生成并登记后再继续。读取并执行 `references/asset-name-mapping.md`。

任一最高优先级规则不满足时，立即返工，不得继续交付。

## 全流程

### 第一步：提取角色和状态版本

1. 读取 `references/01-character-extraction.md` 和 `references/prompt-character-extraction.txt`。
2. 从用户最开始提供的完整文章、推文文案和故事情节中提取全部人物，包括“我”、无名人物及系统等非人类辅助存在。
3. 合并同一人物代称，但将显著视觉状态拆成独立角色图版本，例如“王姨正常”“王姨落水版”。
4. 只输出合法 JSON 数组；每条仅包含 `name`、`aliases`、`description`。

### 第一步之后、第二步之前：询问图片保存目录并确认作品类型

在第二步之前读取 `references/01b-image-output-folder.md`，并询问：

> 本次生成的角色图和场景图需要另存到哪个文件夹？请提供完整文件夹路径。
>
> 本次做“仿真人竖屏”还是“漫剧横屏”？

等待用户同时提供路径和明确类型；已经提供其中一项时只追问缺失项。未获得完整路径与类型选择不得开始第二步。验证目录存在且可写；需要创建目录或额外权限时，先获得用户确认或授权。选择后锁定：全部角色图与场景图均为16:9；最终视频提示词为仿真人竖屏9:16或漫剧横屏16:9。

### 第二步：提取场景和状态版本

1. 读取 `references/02-scene-extraction.md` 和 `references/prompt-scene-extraction.txt`。
2. 提取全部具体物理场景，合并同一空间的代称，忽略没有具体物理画面的抽象地点。
3. 将同一地点的显著视觉变化拆成独立场景版本；保持空间骨架和标志性元素一致。
4. 描述始终采用无人空镜，不出现人物或动物。
5. 只输出合法 JSON 数组；每条仅包含 `name`、`aliases`、`description`。

### 第三步：按已确认类型生成16:9角色图

1. 回查第二步之前已经确认的“仿真人竖屏”或“漫剧横屏”，不得再次询问、不得默认、不得更改。
2. 读取 `references/03-character-image-generation.md`。
3. 根据所选类型使用文件内对应角色风格词，与第一步的完整角色描述组合。
4. 使用可用的图像生成能力，为每个角色状态版本分别生成一张16:9角色设定图；两种类型画幅相同，只切换风格描述词。
5. 同一人物的多个版本保持面貌、年龄、身高、体型和核心辨识特征一致，只改变剧情状态。
6. 依照角色 JSON 顺序立即保存到已确认目录，文件名保留唯一原始资产名与三位生成序号。
7. 登记原始名字、实际文件名、完整路径、角色状态和生成顺序。

### 第四步：生成16:9四视角场景图

1. 回查第二步之前已经选择的类型，不重新选择；找不到选择时立即停止并补问。
2. 读取 `references/04-scene-image-generation.md`。
3. 每张场景图提示词最前面原样加入：`请将图生成四个分格，每个分格是场景的不同视图和角度`。
4. 使用文件内与所选类型对应的场景风格词，再追加第二步的当前场景描述。
5. 每个场景状态版本分别生成一张16:9四分格图；两种类型画幅相同，只切换风格描述词；所有分格不得出现人物或动物。
6. 同一地点的不同状态保持空间骨架、结构和标志物一致。
7. 依照场景 JSON 顺序立即保存到已确认目录，并登记原始名字、实际文件名、完整路径、状态和生成顺序。

### 第五步：生成视频提示词

1. 读取 `references/05-video-prompt-generation.md`。
2. 回查第二步之前锁定的类型。
3. 只读取并执行 `references/director-unified-xiaoliuyue-15s.txt`，严禁读取两份废止的旧导演文件。
4. 仿真人竖屏的最终视频提示词使用9:16与仿真人视觉；漫剧横屏的最终视频提示词使用16:9与3D漫剧视觉。除最终视频比例和视觉风格词外，两种模式完整共用统一文件的28项红线、输出模板、时长、对白、表演、连续性、声音编号和尾镜检查。
5. 每节固定5镜、默认15秒（允许14—16秒），有效声音覆盖13.8—14.5秒，普通接话间隔0.05—0.2秒，动态语速3.5—4.7字/秒且平均不得超过4.7字/秒；对白一般45—68个有效汉字，超出时必须验证理论耗时不超过15秒。
6. 【出场人物】按现场实际存在者完整列出，即使沉默、旁听或位于侧后方也不得省略；上一节在场且未明确离开者继续保留。所有现场人物始终在场，未说话者持续倾听、保持目光与即时反应；站位、坐站状态和朝向继承上一节。
7. 【出场人物】、【出场场景】及主提示词执行精确资产名映射；历史录音、电话声音和群消息不得生成新角色实体或人物分身。不得删减统一提示词中的其他字段。

### 第六步：划分每节正文并设计边做边说

1. 读取 `references/06-section-sizing-and-action-dialogue.md`；只有需要校准示例时才读取 `references/example-section-sizing.txt`。
2. 示例约105—138字符、平均约120字符，只是内容密度参考，不是切割线。
3. 按完整剧情节点划分正文，保持完整台词、连续动作、因果和悬念落点。
4. 一句话结束时即使已经超过120字符，也不得在中间截断；动作没完成也不得强切。
5. 动作与台词可自然同步时，设计为人物边做边说，不机械照搬“正文先写动作、后写台词”的句序。
6. 只有动作妨碍发声、必须先确认结果或剧情明确需要停顿、震惊、犹豫和蓄势时，才保留先后顺序。
7. 内容确实超载时，先调整相邻分节；超长台词只能在已有标点、完整语义或自然停顿处拆分。仍冲突时向用户说明，不擅自删改。

### 第七步：顺序生成并每20节交付

1. 读取 `references/07-sequential-generation-and-delivery.md`。
2. 从用户最开始提供的完整文章开头按顺序处理到结尾，不遗漏、不重复、不倒序、不续写。
3. 每完成一节记录正文结束位置；节号和 `【声音N】` 跨文件连续，不重置。
4. 每20节保存为一个UTF-8 `.txt` 文件；最后不足20节按实际数量保存。
5. 默认命名：`{作品名}_视频提示词_{起始节三位数}-{结束节三位数}.txt`。
6. 按用户要求将视频提示词文件放到桌面；同名文件存在时不静默覆盖。
7. 第20节与第21节等跨文件边界也必须检查人物、资产、场景、道具、时间、轴线、声音编号和动作连续性。

## 结束检查

交付前逐项确认：

- 只读取并执行了统一视频提示词；两份旧导演文件未被读取或引用。
- 类型已在第二步之前确认；全部角色图和场景图均为16:9，最终视频提示词按仿真人竖屏9:16或漫剧横屏16:9输出。
- 每节现场实际存在的人物全部列出并持续在场；人物表、主提示词资产清单与实际画面完全一致。
- 人物和背景只使用资产库中的准确原始文件名；缺少资产已报告并停止对应提示词，未临时编造或近似替代。
- 角色图和场景图已按生成顺序保存到用户指定目录，且可由资产名反查文件。
- 没有按120字符截断完整台词或动作。
- 可以同步的动作与台词已经设计为边做边说。
- 旁白转换和简化未改变原义或丢失主要内容。
- 每节固定5镜、默认15秒且在14—16秒内；有效声音13.8—14.5秒，普通接话0.05—0.2秒，动态语速3.5—4.7字/秒且平均不超过4.7字/秒。
- 每节对白一般45—68个有效汉字；超过时已验证理论耗时不超过15秒；动作与对白同步，尾镜为最后实际说话人，无字幕、可读文字和BGM。
- 原文全部覆盖，20节一文件，文件名与实际节数范围一致。
