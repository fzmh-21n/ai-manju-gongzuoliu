# AI漫剧工作流

把用户的完整文章转成可追踪资产、角色图、场景图和分节视频提示词。严格按七步顺序执行，不跳过强制询问。

## 最高优先级

1. **绝对隔离两套导演提示词。** 用户选择“仿真人竖屏短剧”后，只读取 `references/director-vertical-realistic.md`，禁止读取、参考或借用横屏导演提示词；用户选择“横屏漫剧”后，只读取 `references/director-horizontal-3d.md`，禁止读取、参考或借用竖屏导演提示词。即使当前体系缺少某项规则，也不得用另一套补齐。
2. **准确映射最终图片资产名。** 每节的【本节出场的所有人物】和【本节的所有背景】必须逐字复制最终资产文件名主干（包含既有三位编号和状态后缀，不含扩展名），不得加括号、别名或额外描述。正式分镜开始前必须补齐并锁定所需资产；缺失、重名或无法唯一匹配时停止分镜并返回资产阶段处理，禁止在正式分镜中虚构新资产。读取并执行 `references/asset-name-mapping.md`。

任一最高优先级规则不满足时，立即返工，不得继续交付。

## 全流程

### 第一步：提取角色和状态版本

1. 读取 `references/01-character-extraction.md` 和 `references/prompt-character-extraction.txt`。
2. 从用户最开始提供的完整文章、推文文案和故事情节中提取全部人物，包括“我”、无名人物及系统等非人类辅助存在。
3. 合并同一人物代称，但将显著视觉状态拆成独立角色图版本，例如“王姨正常”“王姨落水版”。
4. 只输出合法 JSON 数组；每条仅包含 `name`、`aliases`、`description`。

### 第一步之后：询问图片保存目录

在第二步之前读取 `references/01b-image-output-folder.md`，并询问：

> 本次生成的角色图和场景图需要另存到哪个文件夹？请提供完整文件夹路径。

等待用户提供路径。未获得路径不得开始第二步。验证目录存在且可写；需要创建目录或额外权限时，先获得用户确认或授权。

### 第二步：提取场景和状态版本

1. 读取 `references/02-scene-extraction.md` 和 `references/prompt-scene-extraction.txt`。
2. 提取全部具体物理场景，合并同一空间的代称，忽略没有具体物理画面的抽象地点。
3. 将同一地点的显著视觉变化拆成独立场景版本；保持空间骨架和标志性元素一致。
4. 描述始终采用无人空镜，不出现人物或动物。
5. 只输出合法 JSON 数组；每条仅包含 `name`、`aliases`、`description`。

### 第三步：确认类型并生成角色图

1. 生成任何角色图前，必须询问用户本次做“仿真人竖屏短剧”还是“横屏漫剧”，并等待明确选择，不得默认。
2. 读取 `references/03-character-image-generation.md`。
3. 用户提供已有角色图或资产包时，先按角色 JSON 核对、建立身份基准、保留原文件并制作更名映射；只为缺失的角色或状态生成新图。未提供时再全量生成。
4. 根据所选类型使用文件内对应角色风格词，与第一步的完整角色描述组合；使用可用的图像生成能力补齐每个缺失角色状态版本。
5. 同一人物的多个版本保持面貌、年龄、身高、体型和核心辨识特征一致，只改变剧情状态。
6. 依照角色 JSON 顺序立即保存到已确认目录，文件名保留唯一原始资产名与三位生成序号。
7. 登记原始名字、实际文件名、完整路径、角色状态和生成顺序。

### 第四步：生成四视角场景图

1. 回查第三步已经选择的类型，不重新选择；找不到选择时才重新询问。
2. 读取 `references/04-scene-image-generation.md`。
3. 每张场景图提示词最前面原样加入：`请将图生成四个分格，每个分格是场景的不同视图和角度`。
4. 使用文件内与所选类型对应的场景风格词，再追加第二步的当前场景描述。
5. 用户提供已有场景图或资产包时，先按场景 JSON 核对并制作更名映射，只补齐缺失场景；未提供时再为每个场景状态版本生成四分格图。所有分格不得出现人物或动物。
6. 同一地点的不同状态保持空间骨架、结构和标志物一致。
7. 依照场景 JSON 顺序立即保存到已确认目录，并登记原始名字、实际文件名、完整路径、状态和生成顺序。

### 第五步：生成视频提示词

1. 读取 `references/05-video-prompt-generation.md`。
2. 回查第三步的类型选择。
3. 若为“仿真人竖屏短剧”，只读取 `references/director-vertical-realistic.md`，严禁读取横屏导演文件。
4. 若为“横屏漫剧”，只读取 `references/director-horizontal-3d.md`，严禁读取竖屏导演文件。
5. 共同层只负责路由、原文范围、资产清单和跨节连续性，不得覆盖所选导演提示词的时长、镜数、标题、字段、台词渠道、声音格式、空间图或自检规则。
6. 【本节出场的所有人物】和【本节的所有背景】逐字使用已锁定的最终资产文件名主干；存在缺失或歧义时先返回资产阶段补齐，不生成正式分镜。
7. 如需为平台安全审核替换风险表达，只做最小范围同义改写，保持剧情事实、人物关系、因果、镜头顺序和核心台词含义不变；无法安全等价表达时报告用户，不得暗改剧情。

### 第六步：划分每节正文并设计边做边说

1. 读取 `references/06-section-sizing-and-action-dialogue.md`；只有需要校准示例时才读取 `references/example-section-sizing.txt`。
2. 旧示例的字符统计只用于理解“按完整剧情节点切分”，不得作为当前所选导演体系的承载量、目标值或切割线。
3. 按完整剧情节点划分正文，保持完整台词、连续动作、因果和悬念落点。
4. 不按固定字符数截断台词或动作；实际承载以所选导演提示词的目标时长、自然朗读、动作占时和连续性规则校准。
5. 动作与台词可自然同步时，设计为人物边做边说，不机械照搬“正文先写动作、后写台词”的句序。
6. 只有动作妨碍发声、必须先确认结果或剧情明确需要停顿、震惊、犹豫和蓄势时，才保留先后顺序。
7. 内容确实超载时，先调整相邻分节；超长台词只能在已有标点、完整语义或自然停顿处拆分。仍冲突时向用户说明，不擅自删改。

### 第七步：顺序生成并每20节交付

1. 读取 `references/07-sequential-generation-and-delivery.md`。
2. 从用户最开始提供的完整文章开头按顺序处理到结尾，不遗漏、不重复、不倒序、不续写。
3. 每完成一节记录正文结束位置；节号和 `【声音N】` 跨文件连续，不重置。
4. 每20节保存为一个UTF-8 `.txt` 文件；最后不足20节按实际数量保存。
5. 默认命名：`{作品名}_视频提示词_{起始节三位数}-{结束节三位数}.txt`。
6. 按用户要求将视频提示词文件放到桌面；同名文件存在时不静默覆盖。
7. 第20节与第21节等跨文件边界也必须检查人物、资产、场景、道具、时间、轴线、声音编号和动作连续性。

## 结束检查

交付前逐项确认：

- 只读取并执行了用户所选的一套导演提示词。
- 每节人物和背景均逐字使用最终资产文件名主干，不含扩展名、括号、别名或描述；不存在缺失、重名或近似误匹配。
- 角色图和场景图已按生成顺序保存到用户指定目录，且可由资产名反查文件。
- 没有按固定字符数截断完整台词或动作。
- 可以同步的动作与台词已经设计为边做边说。
- 台词、OS、画外音、旁白和声音编号均服从所选导演提示词，未被共同层擅自转换或覆盖。
- 每节时长、镜数、标题、字段和自检均服从所选导演提示词；节号及跨节连续性稳定。
- 安全替换若发生，仅替换风险措辞，未改变剧情、镜头顺序或核心台词含义。
- 原文全部覆盖，20节一文件，文件名与实际节数范围一致。
