# 第一步：角色提取

## 输入

- 小说原文
- 推文文案
- 故事情节
- 可选的前置画风提示词

## 目标

提取所有出现过或被明确指代的人物（包括“我”），合并同一人物的多种代称，并为每个人物生成角色设定图描述。系统、外挂、金手指、面板、空间、商城等非人类辅助存在也作为独立角色。

同时识别同一人物在不同剧情阶段出现的显著视觉状态。只要状态变化会影响角色图或后续分镜的一致性，就为该人物额外生成独立的角色状态版本。

## 输出

只输出合法 JSON 数组。每个角色仅包含：

- `name`
- `aliases`：多个代称用英文逗号分隔
- `description`：严格使用固定角色设定模板

同一人物的不同状态分别作为独立数组项输出，并使用可区分的 `name`，例如：

- `王姨正常`
- `王姨落水版`

各状态仍属于同一人物，但每个状态各生成一张角色设定图。

## 角色状态拆分规则

1. 先提取人物的基础/正常状态，再按剧情出现顺序识别显著变化状态。
2. 当服装、整洁程度、身体状况、妆容、年龄阶段、身份伪装或其他关键视觉特征发生明显变化时，拆成独立状态版本。
3. 短暂但对具体场景视觉呈现至关重要的变化也要拆分，例如落水后浑身淤泥、脸部脏污。
4. 状态名采用“人物名 + 简短状态”的方式，确保后续分镜可以明确引用，例如“王姨正常”“王姨落水版”。
5. 各状态继承同一人物不变的核心特征，如基础脸型、年龄、身高、体型和身份；只修改该状态实际发生变化的形象元素。
6. 状态描述必须准确反映对应剧情阶段。例如“王姨正常”可呈现光鲜亮丽的初始状态；“王姨落水版”需呈现落水后的湿发、湿透或沾泥服装、浑身淤泥、脸部脏污等剧情结果。
7. 不要把没有明显视觉差异的普通情绪或动作机械地拆成新版本。

## 基准提示词

执行本步骤时读取包内基准提示词 [prompt-character-extraction.txt](prompt-character-extraction.txt)，保持其核心规则与固定模板，不自行删改硬性要求。

## 核心约束摘要

1. 不遗漏无姓名人物、“我”及非人类辅助存在。
2. 外貌缺失时，依据身份、性格、时代和剧情合理推断。
3. 各角色服装、色彩、气质与轮廓要有明显区分。
4. 服装必须匹配时代与题材。
5. 武器、法宝和关键道具只能采用原文明示内容；没有则写“无”。
6. 不刻意添加或手持普通生活物品、泛职业工具。
7. `description` 包含角色设计板、三视图、特写、细节格和必要的关键物品展示。
8. 同一人物若存在显著剧情状态变化，必须拆成多条角色记录和多张角色图。
