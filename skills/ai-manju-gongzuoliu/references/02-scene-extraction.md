# 第二步：场景提取

## 进入本步骤前的强制条件

必须先完成 [角色图与场景图保存文件夹确认](01b-image-output-folder.md)，获得用户提供的完整文件夹路径并锁定为当前项目图片交付目录。未获得路径时不得开始第二步。

## 输入

- 推文文案
- 故事情节

## 目标

提取文中出现的全部具体物理场景，合并属于同一空间的不同称谓，为每个场景生成可直接用于场景图制作的无人空镜描述。

同时识别同一地点在不同剧情阶段出现的显著视觉变化。只要变化会影响后续分镜的环境连续性，就将它拆成独立的场景状态版本，并分别生成场景图。

## 输出

只输出合法 JSON 数组。每个场景仅包含：

- `name`
- `aliases`：多个代称用英文逗号分隔
- `description`

## 场景提取规则

1. 全量提取文中出现的具体地点，如卧室、教室、街道、森林。
2. 将逻辑上属于同一空间的称谓合并，例如“家中”“客厅”“沙发上”可合并为一个客厅场景，其余称谓放入 `aliases`。
3. 忽略没有具体物理环境的抽象地点，如“心中”“回忆里”。若回忆中呈现了可视化的具体地点，则提取该具体地点。
4. 场景名至少包含四个汉字，优先采用“状态/特征 + 具体地点”或“地点 + 方位”的形式，避免重名。
5. 描述必须包含环境类型、时间/光影、主要陈设、材质及有辨识度的空间细节。
6. 严格采用无人空镜模式：不得出现人物姓名、人物代词、人群或路人。
7. 将人物动作留下的环境结果转化为空镜细节。例如人物坐在破碎椅子上哭，应描述破碎椅子与散落碎片，不描述人物。

## 场景状态拆分规则

1. 先提取地点的基础/初始状态，再按剧情顺序识别环境的显著变化状态。
2. 当同一地点的天气、时间、光照、整洁程度、破坏程度、陈设、季节、年代或其他关键视觉特征发生足以影响画面的变化时，拆成独立场景版本。
3. 每个状态作为独立 JSON 数组项，并分别生成一张场景图。
4. 使用“地点 + 简短状态”或“状态 + 地点”的名称明确区分，例如“整洁的王姨客厅”“淹水后的王姨客厅”。名称仍须不少于四个汉字。
5. 各版本保留地点不变的空间骨架、建筑结构和标志性元素，只修改剧情实际造成变化的部分，保证观众能识别为同一地点。
6. 在 `description` 中写清该版本特有的光影、陈设状态、污损、破坏或环境结果。
7. 不要仅因普通镜头角度变化或无关紧要的轻微变化重复拆分场景。

## 基准提示词

执行本步骤时读取包内基准提示词 [prompt-scene-extraction.txt](prompt-scene-extraction.txt)，保持其核心规则与输出约束，不自行删改硬性要求。
