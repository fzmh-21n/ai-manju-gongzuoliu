# 第一步之后：确认角色图与场景图保存文件夹

## 执行位置

本步骤必须发生在第一步角色提取完成之后、第二步场景提取开始之前。

## 强制询问

继续第二步之前，必须询问用户：

> 本次生成的角色图和场景图需要另存到哪个文件夹？请提供完整文件夹路径。

必须等待用户提供路径，不得自行选择桌面、工作区、临时目录或沿用其他项目的旧路径。用户没有给出路径时，不得进入第二步。

## 路径确认

1. 记录用户提供的完整目标文件夹路径，并将其锁定为当前项目的图片交付目录。
2. 后续第三步角色图和第四步场景图均保存到该文件夹，除非用户明确更改路径。
3. 执行前检查路径是否存在、是否为文件夹以及是否可写。
4. 如果路径不存在，先询问用户是否创建，不能擅自改存到其他位置。
5. 如果路径不可写，明确说明问题并等待新路径或必要授权，不能只展示图片而跳过保存要求。
6. 不得把其他项目的图片混入当前项目目录。

## 按生成顺序保存

1. 角色图严格按照第一步角色 JSON 的顺序生成并保存；同一人物的状态版本按其在列表中的顺序保存。
2. 场景图严格按照第二步场景 JSON 的顺序生成并保存；同一地点的状态版本按其在列表中的顺序保存。
3. 每生成一张图片就立即保存并登记，不要等全部图片完成后再凭记忆重排。
4. 保存时记录生成序号、资产原始名字、资产类型、状态版本和实际文件名。
5. 为确保文件浏览器中能够按生成顺序查看，可在实际文件名前添加同类资产内的三位序号，同时完整保留资产原始名字，例如：
   - `角色图_001_王姨正常.png`
   - `角色图_002_王姨落水版.png`
   - `场景图_001_整洁的王姨客厅四视角.png`
   - `场景图_002_淹水后的王姨客厅四视角.png`
6. 资产清单中必须同时记录可供视频提示词引用的原始名字和带顺序号的实际文件名，避免混淆。
7. 文件已存在时，不得静默覆盖；保留已有文件并使用清晰版本标识，或先请求用户确认。

## 与资产名称映射规则衔接

保存完成后，按 [角色图与场景图资产名称映射规则](asset-name-mapping.md) 维护资产清单。后续【本节出场的所有人物】与【本节的所有背景】引用的是已登记的资产原始名字，必须能反查到目标文件夹中的准确图片文件。
