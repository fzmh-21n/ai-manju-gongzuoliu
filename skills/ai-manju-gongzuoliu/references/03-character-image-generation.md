# 第三步：生成角色图

## 前置条件

- 第一步已经输出角色及角色状态版本的 JSON。
- 每个角色记录的 `description` 已包含角色设定图固定模板及角色具体形象。
- 第一步之后、第二步之前已经询问并获得用户指定的角色图与场景图保存文件夹路径。

## 强制类型确认

生成任何角色图之前，必须先询问用户：

> 本次做“仿真人竖屏短剧”还是“横屏漫剧”？

必须等待用户明确选择，不得自行默认。用户选择后，只使用对应的一套风格描述词作为所有角色图的前置提示词。

## 风格一：仿真人竖屏短剧

前置风格描述词原文：

> 真人风格，亚洲人，真人身材比例，逼真建模渲染材质，电影级后期，真人摄影的柔和氛围，精致细节，超高清，白色背景。

## 风格二：横屏漫剧

前置风格描述词原文：

> 超写实3D二次元渲染，影视级动漫风格，电影级光影，柔和自然光，皮肤通透的次表面散射，细腻的材质纹理，干净的轮廓线条，景深效果，4K超高清，8k分辨率，细节拉满，写实比例建模，游戏CG质感，真实毛发/布料质感，高对比度，强烈的表情张力，轻风格化，整体参考高规格角色资产图与游戏角色设定图的渲染效果。

## 执行流程

1. 读取第一步输出的全部角色记录，包括同一人物的不同状态版本。
2. 询问并确认本次作品类型。
3. 选择与作品类型完全对应的前置风格描述词。
4. 用户提供已有角色图、文件夹或 ZIP 时，先逐张核对内容与最终角色 JSON；保留原文件不覆盖，并建立“原文件名 → 最终文件名”对照表。已有图片不得重复生成。
5. 为同一人物选定稳定的身份基准图；状态变体必须引用该基准，只改变剧情要求的状态，不把静态资产图当作表情或逐镜表演来源。
6. 将风格描述词与缺失角色记录的完整 `description` 组合为提示词，只生成缺失的角色或状态版本；未提供已有资产时才全量生成。
7. 每个必要角色状态版本分别保留一张角色设定图，不得合并或遗漏。
8. 同一人物的多个版本保持基础面貌、年龄、身高、体型和身份辨识特征一致，只呈现对应状态的差异。
9. 同一作品中的所有角色统一采用已选择的风格，不在生成过程中混用两套描述词。
10. 按角色 JSON 顺序分配三位编号并确定唯一最终文件名；登记身份基准、状态关系、实际文件名和路径，后续按 [资产名称映射规则](asset-name-mapping.md) 精确引用。
11. 按 [图片保存文件夹规则](01b-image-output-folder.md) 保存最终资产；交付前核对 JSON、实际图片和映射表数量及名称一一对应。

## 输出要求

- 输出第一步列出的全部角色图。
- 同一人物的不同状态各自有独立图片和对应状态名称。
- 保持第一步提示词规定的白色或浅色干净背景、角色设计板布局、三视图与细节展示。
- 交付时明确列出每张角色图的最终文件名主干、实际文件名和映射关系，不得让后续视频分镜依靠描述猜测资产。
- 不得只在对话中展示图片而漏存用户指定文件夹。
